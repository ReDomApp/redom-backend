ReDom is a social and communication platform with separate mobile and web clients backed by a domain-oriented TypeScript API. This overview maps the product areas documented by the current master repository.

## Product surfaces

- **Mobile:** `artifacts/redom-frontend`, the Expo/React Native application.
- **Web:** `artifacts/redomweb`, a separate TypeScript, React, and Vite application.
- **Backend:** `artifacts/redom-backend`, the shared Express 5 API and domain services.
- **Documentation and Help:** separate ReDom documentation and help artifacts are also present in the workspace.

The clients share backend services, but the web implementation is a distinct application and should not import React Native components to achieve parity.

## Backend domains

The root backend README identifies these implemented domain areas in source:

- Account registration, authentication, sessions, login history, recognized devices, two-factor authentication, and recovery codes.
- Profiles, profile media, sharing, privacy, and account settings.
- Feed, posts, comments, reactions, saves, shares, mentions, stories, and polls.
- Friends, requests, followers, following, blocking, muting, and restrictions.
- Search and search history.
- Direct and group messaging, message attachments, read receipts, reactions, forwarding, drafts, link previews, and encrypted media/conversation cryptography.
- Group permissions, approvals, reports, invites, and scheduled calls.
- Voice/video calls and call links.
- Business messaging profiles and public groups.
- Events, RSVPs, locations, covers, and recurring events.
- Marketplace listings, categories, interactions, reviews, and transactions.
- Payments, subscriptions, refunds, provider webhooks, and transaction records.
- ReDom Stars payments and gifting.
- ReDom AI chat, localization, image generation/editing, image intelligence, file analysis, voice transcription, and AI quotas.
- ReDom video generation and Movie Studio production workflows.
- Support, bug reports, appeals, reports, and moderation records.
- ReDom OAuth and MCP integration endpoints.

This is a domain inventory, not a guarantee that every feature is enabled for every account or deployed client.

## API organization

HTTP routes are registered under `artifacts/redom-backend/src/routes`. Important route modules include authentication, profiles, feed, friends, messaging, calls, events, marketplace/product, payments, refunds, Stars, AI, support, and Aurelink.

The route registry and middleware are the authoritative sources for exact endpoint paths, authentication requirements, and request behavior. This overview intentionally avoids inferring undocumented API contracts from filenames alone.

## Security and trust boundaries

The engineering handbook treats security as product behavior. Important implementation themes include:

- Server-side authentication and authorization.
- Account and resource ownership checks.
- Session and recognized-device controls.
- Two-factor authentication and recovery flows.
- Rate limiting and request validation.
- Provider-side payment verification and webhook verification.
- Idempotency and atomic fulfillment for payment-sensitive operations.
- Secure handling of encrypted messaging media.
- Data minimization and secret protection.

The backend is authoritative for account, payment, and security outcomes. A client-side success state is not proof that a transaction or protected action completed.

## ReDom payments

The backend contains payment services and routes for transactions, saved payment methods, Stars, refunds, and provider callbacks. The engineering handbook documents card processing separately from supported bank-transfer flows. Provider support and current availability must be checked against the current implementation and provider account before being stated as live.

## AI and media

ReDom's AI-related code includes chat/media services, image-engine orchestration, image security and quotas, video generation, and Movie Studio. The repository also contains separate image and video worker artifacts. Their runtime prerequisites and feature limits are documented separately in [AI and media systems](/ai-systems/overview).
